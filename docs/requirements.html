無料PDF編集ツール「PDF Page Editor」要件定義書

PDFのページの並べ替え・削除・回転・結合・表示倍率の変更・ファイルサイズの圧縮を、社外にファイルを出さずに無料で行うChrome拡張機能について、目的・要件・構成・運用をまとめます。

1概要

1.1 背景

  • 社内で「PDFのページを並べ替えたい・不要なページを消したい・複数のPDFを1つにまとめたい」という作業が日常的に発生している。
  • これらの操作には有料ソフト（Adobe Acrobat Pro など）が必要で、全員分のライセンスを用意するとコストがかかる。
  • 無料のオンラインPDFサービスは手軽だが、社外秘の資料を外部のサーバーにアップロードすることになり、情報漏えいのおそれがある。

1.2 目的

  • PDFのページ単位の編集を、追加費用なしで社員全員が行えるようにする。
  • PDFを外部に送信せず、各自のパソコンの中だけで処理できるようにする。
  • 説明書を読まなくても使えるほど、操作をシンプルにする。

1.3 対象範囲

区分内容
対象ページ単位の編集（並べ替え・削除・回転・結合）、編集結果のPDF保存、サムネイルの表示倍率の変更、ファイルサイズの圧縮
対象外ページ内の文字や画像の編集、注釈・署名の追加、OCR、PDF以外の形式への変換、パスワードの設定・解除、クラウド保存や共有

2用語

用語意味
拡張機能Google Chromeに機能を追加する小さなプログラム。本ツールはこの形で提供する。
編集画面ツールバーのアイコンを押すと新しいタブで開く、本ツールの操作画面（editor.html）。
元ファイル利用者が読み込んだPDF。本ツールは元ファイルを書き換えない。
ページ並び編集画面上の現在のページの順番と向き。保存時にこの内容でPDFを作る。
デベロッパー モードストアを通さずに拡張機能をフォルダから読み込むための、Chromeの設定。
Manifest V3現行のChrome拡張機能の仕様。manifest.json に記述する。

3利用者と利用環境

3.1 想定利用者

  • 社内の全社員。パソコン操作に慣れていない人も含む。
  • 導入作業も利用者本人が行う前提とし、導入手順書を別に用意している。

3.2 想定利用シーン

  • スキャンした書類のページ順が逆になっているので並べ替える。
  • 見積書・請求書・添付資料を1つのPDFにまとめて送付する。
  • 横向きに取り込まれたページを正しい向きに直す。
  • 提出用に、社内向けのページ（メモ・検討資料）を削除する。

3.3 動作環境

項目要件
OSWindows 10 / 11、macOS（Chromeが動作するもの）
ブラウザGoogle Chrome の最新安定版（Manifest V3 と ES Modules に対応していること）
ネットワーク不要（導入時のZIP取得を除く）
権限拡張機能として特別な権限は要求しない（manifest.json に permissions の指定なし）

6システム構成

6.1 全体像

サーバーを持たず、すべての処理を利用者のChromeの中で行う。表示用と書き出し用に、役割の異なる2つのライブラリを使う。

PDFファイルドラッグ＆ドロップ／ファイル選択
→
解析pdf.js（表示用）と pdf-lib（書き出し用）で別々に読み込む
→
ページ並びの編集順番・向き・削除をデータとして保持（元のPDFは触らない）
→
保存pdf-lib で必要なページだけを新しいPDFにコピーしてダウンロード

6.4 データの持ち方（editor.js）

データ内容

7設計上の判断

Webサービスではなく、Chrome拡張機能にした

サーバーが不要で費用も情報漏えいの経路もなく、アイコン1つで起動できるため。中身は通常のWebページなので、必要になればWebアプリにも転用できる。

表示と書き出しで別のライブラリを使う

pdf.js は描画に強いがPDFを書き出せず、pdf-lib は書き出せるが描画できない。それぞれの得意分野に分けた。

編集は「ページ並び」というデータの上で行い、保存時にだけPDFを作る

操作が軽く、元に戻す・やり直しを簡単に実現できる。元のPDFは最後まで変更しない。

暗号化PDFは読み込み時点で断る

pdf-lib は暗号化されたPDFを正しく書き出せないため、編集した後で保存に失敗するより、最初に分かるほうが利用者の手間が少ない。

サムネイルは1枚ずつ順番に描画し、解像度は3段階に限る

大量のページを同時に描画するとメモリが不足するため。倍率を少し変えただけでは描き直さず、画質が足りなくなったときだけ高解像度で描く。

圧縮は「画像の再圧縮」と「ページの画像化」の2方式にする

文字を残したまま確実に効くのは、PDF内のJPEG画像の縮小・再圧縮。JPEGはブラウザ自身で読み書きでき、追加のライブラリが要らない。文字中心のPDFでも小さくしたい場合のために、文字が選択できなくなることを明示したうえでページの画像化も用意した。画像の表示サイズまでは解析せず、「最も大きいページ全体に表示されても指定の解像度を下回らない大きさ」を上限にしている。

ライブラリはCDNを使わず同梱する

オフラインで動作させ、外部への通信をゼロにするため。拡張機能のセキュリティ方針（CSP）上もこの方が確実。

8制約・既知の制限

項目内容回避策
暗号化PDFパスワード保護・暗号化されたPDFは読み込めない。パスワードを外したPDFを使う。将来対応候補（FR-F4）。
しおり元ファイルのしおり（目次）は保存後のPDFに残らない。将来対応候補（FR-F3）。
入力フォーム入力欄付きのPDFは、保存後に入力欄が正しく動かない場合がある。入力を済ませてから編集する。
大きなファイルPDFの内容をメモリに保持するため、数百MB級のPDFでは動作が重くなる可能性がある。分割してから編集する。上限は今後計測する。
圧縮の対象「軽め」「標準」で縮小するのはJPEG形式（グレー・RGB）の画像のみ。PNG形式の画像、CMYKの画像、白黒2値のスキャン画像、文字やフォントは圧縮しない。文字が中心のPDFは「最大」を使う。
圧縮「最大」ページ全体を画像にするため、文字の選択・検索、リンク、しおりが失われる。提出用など文字情報が必要なPDFでは「標準」を使う。
編集履歴元に戻す履歴は、タブを閉じると消える。こまめに保存する。

9.3 受け入れ基準

  • 9.2 の項目がすべて合格していること。
  • 試用者が、手順書のみで導入と「並べ替え→保存」を完了できること。

10配布・運用

10.1 配布方法（現行）

  1. ソースコード・資料・配布用ZIPはすべて GitHub で公開する。
  2. 資料（本書・導入手順書）は GitHub Pages で公開する。リポジトリの docs/ フォルダの内容がそのままサイトになる。
  3. 配布用ZIPは GitHub Releases に置く。導入手順書のダウンロードボタンは常に最新版を指す。
  4. 社内には、導入手順書のURLを案内する。利用者は手順書に沿ってZIPを展開し、Chromeの「デベロッパー モード」から読み込む。

10.2 バージョン管理と更新

  • 版は manifest.json の version で管理する。機能追加は 1.x.0、不具合修正は 1.x.y と上げる。
  • リリースするときは、manifest.json の版を上げてコミットし、v1.2.0 のような版名のタグを付けてプッシュする。GitHub Actions が配布用ZIPを作り、Releases に登録する。
  • 利用者は、新しいZIPでフォルダを入れ替えて拡張機能を再読み込みする（手順書に記載）。
  • 同梱ライブラリは、脆弱性情報を確認したうえで年1回程度見直す。

10.3 将来の配布方法の候補

方法長所短所
GitHub Releases のZIP＋手動読み込み（現行）費用なし、すぐ始められる利用者の作業が多い。自動更新されない。
Chrome ウェブストア（限定公開）「Chromeに追加」ボタンだけで導入でき、自動更新される開発者登録料（初回のみ約5ドル）とストアの審査が必要
Google Workspace 管理コンソールから一括配布利用者の作業がゼロ。全社に強制的に導入できるGoogle Workspace の管理者権限が必要。ストアへの登録が前提になる

11リスクと対策

リスク影響対策
会社のChrome管理ポリシーで、デベロッパー モードや拡張機能の追加が禁止されている大 導入できない展開前に情報システム担当へ確認する。禁止の場合はストア経由・管理コンソール配布に切り替える。
利用者が拡張機能のフォルダを移動・削除する中 ツールが使えなくなる手順書で「ドキュメント」フォルダに置くよう指定し、注意を明記している。
Chromeの仕様変更で、フォルダからの読み込みが制限される中 新規導入ができなくなるChromeの更新情報を確認し、必要ならストア配布に移行する。
リポジトリと資料が社外からも見える小 社内事情が外部に知られる秘密情報・個人名・連絡先・社内URLを載せない。公開前とリリースのたびに内容を確認する。
同梱ライブラリの脆弱性中 細工されたPDFを開いたときの安全性ライブラリの更新情報を定期的に確認し、更新版を配布する。
特殊なPDFで表示や保存が崩れる中 誤ったファイルを送付するおそれ元ファイルを変更しない設計とし、保存後のPDFを確認するよう案内する。
